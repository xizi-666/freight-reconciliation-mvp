# 项目设计说明

## 1. 项目目标

围绕运输完成、运单归集、重量核验、合同计费、差异确认与结算审批，减少人工查合同和重复核对。访谈报告提出月差异项从 1200 降至 400、对账周期从 15 天降至 7 天；这些是业务目标陈述，须以统一统计周期和业务日志复核。

## 2. 首期范围

- 只读汇集 TMS、计费系统、财务 ERP 中经授权的业务数据。
- 校验业务编号、事件时间、合同价目版本和数据新鲜度。
- 用确定性规则复算重量、费率、附加费和金额。
- AI 从合同和凭证中检索引用，生成差异解释、待确认字段与原因摘要。
- 将缺证据、版本冲突、月中换价、时点歧义、低置信和接口故障转交具名人工。
- 保存资料版本、规则版本、事实引用、计算过程、人工修改和签核记录。

## 3. 明确排除

模型不裁定合同变更、赔付或争议的最终责任；系统不自动批准结算、不付款、不扣费、不覆盖原始记录。

## 4. MVP 流程

1. 字段与接口盘点，确认业务编号、事件时间、版本字段和授权范围。
2. 用历史争议样本回放，进行确定性计费和证据检索。
3. 由对账专员盲评解释是否可采纳，并由审计人员重建处理链。
4. 在两家承运商范围内并行试点，保持原审批流程。
5. 每周收集误判和未解决问题；命中停止条件即暂停并复盘。

## 5. 验收建议

硬约束：计费结果可重现率 100%；未授权扣费为零；每笔建议附计算过程和来源；合同变更、赔付由授权人员判断。过程指标可包括解释采纳率、缺证据转人工率、版本冲突识别率、接手确认时间和人工复核耗时。统计前须确定分母、排除项与周期。

## 6. 尚待验证

重量字段存储及优先级、全量字段字典、接口清单和更新粒度、系统生成版本号的主责、转人工接手时限、合同澄清责任人、评价记录留存期限。
